# Lessons

Each fixed convention in `SKILL.md` and each rule in `PROTOCOL.md` exists because a real audit run broke without it. The runs are described here without naming the audited projects: the point is the failure mode in the audit, not the target.

## The clone registered the target's skills into the auditor

An early version of this protocol cloned the target into a subdirectory and started the agent session in the parent, on the theory that files below cwd would be read as data. The harness discovered the clone's `.claude/skills` anyway and registered 13 target skills mid-run, including one that opens pull requests via `gh`. `gh` was already authenticated on that host, with write scope to the operator's repositories. A generically named `verify` skill from the target was scoped to win for files under the clone, so a routine verification step would have run supplier instructions.

The audit only noticed because the harness announced the new skills, and only understood the severity because the target's own manifest documented its `gh` use. **Disclosure by the subject substituted for detection by the instrument.**

Result: host qualification (Convention 0, the nine probes), clone path demoted to hygiene, Tier 0 means no clone at all.

## The self-authored containment check was vacuous

The next revision had the session record its ingestion roots before cloning and diff them after. A file planted outside that self-authored root list was ingested and surfaced as a skill while the check reported "diff empty, GREEN eligible." A session that authors its own root list has sealed a domain of its own choosing.

Result: "do not grade a control by its author." The first control that held was one whose reference value the session could not write (container runtime inspection from outside).

## A repair made the instrument worse

A remediation added a baseline script resolved by relative path, which inside a clone meant a repo shipping that path got code execution before the credential scrub. Another added a mandatory `rg --follow -a` profile that followed symlinks out of the tree and printed private key material.

Result: instrument repairs are re-tested as new; never follow symlinks out of a target tree; the old generator was quarantined rather than patched in place.

## The generator contradicted itself

A generated prompt put the session in `~/sandbox/audits/` in its header and forbade cwd at or below `~/sandbox/audits/` in its body. The auditor correctly ran in the header location and then logged a false deviation against a rule that should never have been written.

Result: Convention 1 is directional (forbid the clone path, never its ancestor) with a pre-emit authoring check.

## The brief inherited an overclaim from a README

The intake brief said a compatibility file claimed test evidence across eight agents, taken from the README's description of that file. The file itself was honest (most rows marked untested). The overclaim was in the README pointer.

Result: Convention 16 (grade against the artifact), and intake premises are written as questions for the auditor.

## The search tool was not what it said it was

On one host, `grep` was a shell function re-execing another binary as `ugrep` with `--ignore-files` baked in. `grep --version` reported the embedded engine. Two identical marker files, one listed in a sibling `.gitignore`, were planted: the default `grep` found one, system `grep` and Python `re` found both. **A target can blind the default search instrument by shipping an ignore file.** Separately, the same function mis-parsed a bracket ERE and produced a confident wrong count.

Result: identify every instrument, corroborate every negative under two engines with character-identical patterns.

## Operator config collided with target vocabulary

A target's CRITICAL finding centred on a config key called `autoMode`. The auditing host's own agent settings file carried an unrelated top-level key with the same name, written by the operator's tooling. A later grep for the key would have hit the operator's file.

Result: on a working machine, a hit is not a finding until its provenance is established.

## The installer was someone else's package

A repo's README install line (`npx <tool> add <repo>`) looked like it ran the repo's code. It resolved to a package published by a different organization, which transmitted source, skill names, file paths, and an inventory of installed agents. The audited README did not disclose this.

Result: resolve every installer to its publisher; installer telemetry is part of the target's install surface.

## CI enforced the absence of AI-authorship trailers

A repo's validator hard-failed on `co-authored-by` and "generated by" strings, and string-concatenated its own patterns so it would not trip itself. Every commit was trailer-free, which on this repo proves nothing.

Result: record authorship as undetermined when the absence is enforced.

## A keyed pilot was offered as a menu option

An older generator offered a "Gate 5" keyed pilot as an intake choice, which let a click override the no-credentials rule.

Result: no gate above 4; fixed conventions are never surfaced as options.

## The sandbox held, and the report was still the breakout

A container with all capabilities dropped, no network, read-only rootfs, and zero host mounts was attacked with symlink escapes, a write-through target, and a repo-supplied RCE. The RCE ran and reached nothing. But the report crosses the boundary by design, and three channels through it were verified: terminal escapes that execute when a human `cat`s the file, repo-chosen filenames that inject into shell copy-out, and report prose that enters the next agent as instruction.

Result: isolation contains execution, not influence. Strip escapes from the stream, extract by fixed name, treat the report as untrusted permanently.

## Open question

Whether loading third-party instruction files into a live agent session (Gate 4 for a skill repo) needs its own adjudication, distinct from executing third-party code. One audited repo had 343 lines of inert stdlib code and about 37 KB of prose that enters a session as instruction. Gate 4's protections are built for the former.
